# Deploying NAVI

This covers a real deployment on Render. Steps marked **[YOU]** require a human with
account access — they are legal/business actions I (or any AI agent) should not and
cannot take on your behalf.

## 1. Prerequisites

- **[YOU]** A Render account, with billing set up.
- **[YOU]** An Anthropic API account with billing set up.
- **[YOU]** A domain (optional but recommended for `COOKIE_DOMAIN` / CORS).

## 2. Business Associate Agreements — do this before any real customer data touches the system

NAVI stores PHI (insurance, claims, medications, visits). Under HIPAA, every vendor
that touches that data must have a signed BAA with you before it's live with real
customers.

- **[YOU]** **Render**: Workspace Settings → Compliance → request HIPAA-enabled
  workspace / BAA. Render will email a BAA to sign. Do this before deploying
  real data — a HIPAA-enabled workspace has to be requested up front.
- **[YOU]** **Anthropic**: In your organization's console, activate the HIPAA-ready
  configuration under Data & Privacy and accept Anthropic's BAA. Note: covered
  models require 30-day data retention — zero-data-retention (ZDR) is
  incompatible with BAA coverage. Confirm the model you're using
  (`claude-sonnet-5` in `.env`) is on Anthropic's current covered-models list.
- **[YOU]** **Embeddings provider** (if you enable `VOYAGE_API_KEY`): confirm Voyage
  AI's current BAA status before sending real document text to it. Until then,
  leave `VOYAGE_API_KEY` unset — the app falls back to a local, non-external
  embedding provider (`app/rag/embeddings.py`).
- **[YOU]** **Payer/clearinghouse** (if you enable `ELIGIBILITY_PROVIDER=availity` or
  similar): that contract will include its own BAA as part of trading-partner
  enrollment.

None of the above can be completed by editing code or config — they're contracts
that require a human signatory, generally with legal review.

## 3. Generate secrets

```bash
# Field-level encryption key for PHI columns — back this up in your secrets
# manager's own backup, not in git. Losing it makes existing encrypted data unrecoverable.
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`JWT_SECRET` can be auto-generated by Render (`render.yaml` sets `generateValue: true`).

## 4. Deploy

```bash
# from the repo root, with the Render CLI installed and authenticated
render blueprint launch
```

Or connect the GitHub repo in the Render dashboard and it will pick up `render.yaml`.
Fill in every `sync: false` env var manually in the dashboard before the first deploy —
`render.yaml` intentionally leaves secrets blank rather than letting them be committed.

## 5. Enable pgvector and run migrations

Once `navi-db` is provisioned, open its psql shell (Render dashboard → navi-db →
Connect) and run:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Then, from the `navi-backend` service shell (Render dashboard → Shell):

```bash
alembic upgrade head
```

## 5b. Cross-site cookies (important)

Auth uses httpOnly cookies, not bearer tokens in JS. `navi-backend.onrender.com` and
`navi-frontend.onrender.com` are different subdomains under a public suffix, so
browsers treat them as **cross-site** — `render.yaml` sets `COOKIE_SAMESITE=none`
for that default setup (requires `COOKIE_SECURE=true`, already the default). If you
later put both services under one custom domain (e.g. `app.yourdomain.com` +
`api.yourdomain.com`), switch `COOKIE_SAMESITE=lax` and set
`COOKIE_DOMAIN=.yourdomain.com` — same-site cookies are the safer default and CSRF
exposure is lower.

## 6. Verify

- `GET https://<backend-url>/api/health` → `{"status": "ok", ...}`
- `GET https://<backend-url>/api/ready` → `{"status": "ready"}` (confirms DB connectivity)
- Register a test account through the frontend and send a chat message.

## 7. Before turning on real customer signups

See [`COMPLIANCE_CHECKLIST.md`](COMPLIANCE_CHECKLIST.md) — BAAs above are necessary
but not sufficient for HIPAA compliance; workforce training, a risk assessment, an
incident response plan, and a privacy/security officer designation are also required
and are **not** things this codebase can provide for you.
